# Електрика — інтерактивний практикум

Сайт на TypeScript, Vite та Three.js WebGPURenderer. Вісім окремих сторінок лабораторних мають намальовані лабораторні установки з інтерактивними приладами, журнал вимірювань, розрахунки, теорію та контрольні питання. Взято підхід до рендерингу із сусіднього проєкту `wawes`; його код і файли не змінювалися.

Публікацію через GitHub Pages готує workflow `.github/workflows/pages.yml`.

## Запуск

Потрібен Node.js, сумісний із Vite 8 (22.12+ або 24+).

```sh
npm ci
npm run dev
```

Локальна адреса: `http://127.0.0.1:5174/`. Для production:

```sh
npm run build
npm run preview
```

Збірка лежить у `dist/` і придатна для статичного хостингу. Маршрути використовують hash: `#/lab/1` … `#/lab/8`, тому серверні правила маршрутизації не потрібні.

## GitHub Pages

Workflow запускається на push, pull request і вручну через Actions → Check and deploy → Run workflow. Деплой виконується лише з основної гілки (`master`); pull request проходить перевірки без публікації.

Перед публікацією виконуються `npm ci`, математичні тести, TypeScript/Vite build та всі браузерні тести саме production-збірки за шляхом `/labs/`. Публікується тільки `dist/`. Секрети або персональні токени не потрібні: deploy використовує `GITHUB_TOKEN` з `pages: write` та `id-token: write`.

У Settings → Pages → Build and deployment обрати **GitHub Actions**. Pages має бути доступним для тарифу й видимості репозиторію. Очікувана адреса: <https://hamak-en.github.io/labs/>.

Локальна перевірка цієї самої збірки:

```sh
PAGES_BASE_PATH=/labs/ npm run build
E2E_PREVIEW=1 npm run test:e2e
```

`PAGES_BASE_PATH` визначає корінь production-сайту; без нього локальна збірка використовує `./`. Hash-маршрути працюють при відкритті прямого посилання на будь-яку лабораторну.

## Можливості

| Робота | Інтерактивність |
| --- | --- |
| 1. Міст Уітстона | Перетягування контакту реохорда, ручка магазину опору, гальванометр, R₁ / R₂ / послідовне / паралельне з’єднання |
| 2. Компенсація ЕРС | Два елементи, перемикання еталона, контакт реохорда й нульовий індикатор |
| 3. Температура й опір | Водяна ванна, нагрівач, термометр, перемикання щупів та поступове нагрівання зразків |
| 4. Діод | Намальований діод зі зміною полярності, регулятор напруги, амперметр і вольтметр |
| 5. Осцилограф | Осцилограф з екраном, ручками, режимом XY та звуковим генератором |
| 6. Закон Ома для AC | ЛАТР, реостат, вилучення конденсатора, вставляння осердя, покази A і V |
| 7. Коефіцієнт потужності | Реальний перемикач лампи/котушки, світіння ламп, ватметр, A і V |
| 8. Міст Сотті | Два конденсатори, контакт реохорда, джерело AC та нульовий вольтметр |

Власні вимірювання вводяться в редаговану таблицю. Кнопка «Записати покази приладів» додає поточний вимір з установки з позначкою «Модель». Редагування демонстраційного показу переводить його в категорію власних даних. Увімкни живлення на установці; у нульових методах запис доступний після балансування. Ручки й контакт можна перетягувати або регулювати стрілками клавіатури. Натискання на гніздо вимірювального приладу від’єднує або відновлює провід. На вузькому екрані стенд можна прокручувати горизонтально. Біля розрахунків похибки наведено прийняті припущення.

Невідомі параметри зразків не показуються на стендах або в панелі параметрів: Rₓ, ℰₓ, Cₓ, температурні R₀/α/ΔW, індуктивність котушки та зсув фаз навантаження. Числові результати з’являються після вимірювань і розрахунків у журналі. Контакти мостів налаштовуються вручну; калькулятори з’єднань початково порожні.

Дані зберігаються в `localStorage` окремо для кожної роботи. Вони не надсилаються на сервер. Є CSV-експорт із UTF-8 BOM, одиницями, джерелом даних та повідомленнями про помилки. Непотрібні виміри можна видаляти окремими рядками. Максимум — 200 вимірів на роботу.

## Рендеринг

Прилади, дроти, шкали, пробірки, реохорд і перемикачі намальовано у SVG. Прозорий WebGPU-шар додає умовну анімацію руху заряду та промінь всередині екрана осцилографа. Кожен стенд має окреме компонування й діючі елементи керування; самостійних графіків на основному екрані немає.

TSL компілюється в WGSL для WebGPU. На GPU обчислюються положення частинок у проводах та вершини променя осцилографа. Числові покази, прогрівання й регресія обчислюються у TypeScript. Осцилограф має спільне калібрування сітки, WebGPU та Canvas: Y — 2 В/поділку; X — 2 мс/поділку в розгортці або 1 В/поділку в XY та 20 В/поділку в режимі чутливості. Нуль у центрі, додатна напруга Y спрямована вгору. Рух крапок показує роботу кола умовно; прогрівання термостата прискорено для навчальної демонстрації.

Якщо WebGPU недоступний, Three.js використовує WebGL 2. Якщо GPU-рендерер не ініціалізується, працює Canvas 2D з тією самою моделлю. Для перевірки резервного режиму додати `?renderer=canvas` перед hash: `/?renderer=canvas#/lab/5`. Фактичний backend доступний в атрибуті `data-backend` елемента `#bench`.

Приховані сторінки не анімуються. Налаштування `prefers-reduced-motion` зупиняє анімацію на старті; промінь і частинки залишаються видимими. Інтерфейс підтримує вузькі екрани та керування вкладками клавіатурою.

WebGPU завантажується окремим модулем після інтерфейсу. Його доступність визначається браузером і середовищем запуску; локальна розробка працює на localhost, хостинг — на HTTPS.

## Перевірки

```sh
npm test
npm run build
npm run test:e2e
```

Математичні перевірки: рівновага мостів, відновлення невідомих величин, температурна регресія, одиниці, резонанс, індуктивність та допустимі покази потужності. Браузерні перевірки: усі 8 стендів, перетягування контакту, ручки клавіатурою, провід, прогрівання, полярність діода, осердя та конденсатор, навантаження, справжній сигнал на WebGPU-екрані, журнал, CSV і мобільний fallback.

Playwright налаштовано на встановлений Google Chrome (`channel: 'chrome'`) і запускає його в ізольованому тестовому профілі. У GitHub Actions браузерні перевірки запускаються на macOS із Chromium від Playwright, щоб перевіряти WebGPU через Metal. Деплой запускається на Ubuntu. Локально потрібен встановлений Chrome.

## Файли

- `src/config.ts` — параметри, формули та пояснення робіт.
- `src/answers.ts` — розгорнуті відповіді на всі 44 контрольні питання: пояснення, виведення та структуровані формули MathML.
- `src/uncertainty.ts` — пояснення похибок у теорії всіх робіт, походження формул і обмеження поточної обробки журналу.
- `src/physics.ts` — моделі, розрахунки й регресія.
- `src/workbench.ts` — малюнки восьми стендів та взаємодія з ними.
- `src/apparatus-renderer.ts` — прозорий WebGPU/WebGL та Canvas fallback.
- `src/main.ts` — сторінки, журнал і взаємодії.
- `src/storage.ts` — локальне збереження та CSV.
- `src/source.json` — питання, обладнання та посилання на рисунки з Markdown-описів.
- `public/docs/` — копія описів та 16 вирізаних рисунків.
- `.openai/hosting.json` — ідентичність і статична конфігурація Sites.

Демонстраційні моделі призначені для вивчення залежностей і не є результатами реального лабораторного досліду. ВАХ діода має задані ілюстративні параметри; пробій не моделюється. Температурна модель напівпровідника описує власну провідність, і оцінку ΔW слід трактувати в її межах.

Обмеження симуляції, для яких у PDF немає чисел, не подаються як характеристики реальних приладів. Програма не відтворює всі перемикачі та захисти оригінальних установок.


У роботі 1 кожен вимір зберігає з’єднання R₁ / R₂ / послідовне / паралельне. Середні та граничні похибки рахуються окремо для цих чотирьох серій. Порівняння з’єднань використовує тільки виміряні R₁ і R₂, не приховані номінали. Попередні рядки без метаданих з’єднання зберігаються й не змішуються з новими серіями.

Похибку мостового виміру обчислено за формулою зі с. 7: δ = ΔR/R + Δl₁/l₁ + (ΔL + Δl₁)/l₂; ΔRₓ = Rₓδ. У журналі доступні ΔR (Ом), Δl₁ та ΔL (см), а також відносний результат у %. Для запису з моделі початково ΔR = 0,001R (явне припущення для класу 0,1), Δl₁ = ΔL = 0,1 см. Значення можна змінити за паспортом та прийнятим правилом відліку. Крок магазину 1 кОм не є похибкою. Для середнього наведено середню граничну похибку без зменшення систематичних складових на √N; для перевірки з’єднань використано поширення граничних похибок першого порядку.

У теорії кожної роботи є розділ «Як визначається похибка». Він відрізняє формули й припущення методички від додаткових оцінок поширення похибок. Числові похибки в журналі реалізовано для робіт 1, 2 та 8; для робіт 3–7 наведено потрібні вихідні невизначеності та формули, але без вигаданих паспортних точностей і без автоматичного числового розрахунку похибки.
